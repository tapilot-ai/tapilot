# 后台屏技术验证

**实验性功能，仅 Debug 可用，默认关闭。** 当前实现通过用户明确授权的 Shell 辅助创建、读取和操作独立显示区域。开启“用于聊天任务”后，普通聊天可操作独立屏幕中的应用；兼容性试用位于高级选项。详见[当前设置说明](shell-assisted-display.zh.md)。

## 设置与试用

从 **设置 → 开发实验 → 后台屏幕（实验性）** 进入，按照[手机内设置说明](shell-assisted-display.zh.md)完成授权、配对和连接，再点击 **试用后台屏幕**。允许悬浮预览后，点击悬浮屏内的按钮，观察实际测试结果。打开设置页本身不会创建副屏。

Beta 和 Release 不包含实验 Activity、服务及恢复权限。建议使用独立的 `-Pe2eVerification` 测试包，避免覆盖日常安装。

## 系统能力检查

内置计数器试用以 480 × 800 像素创建 VirtualDisplay，使用 OWN_CONTENT_ONLY 防止镜像主屏。ImageReader 读取副屏实际帧，Presentation 提供无业务副作用的测试按钮。Shell 辅助将手势限定到当前会话拥有的非零 displayId；点击计数只在测试按钮实际收到事件时增加。

手动试用的截图保留在内存中，不发给模型，不自动导出。单独启动 Agent 试用时，会将测试屏截图发送给已配置的模型，并使用应用内报告存储。悬浮预览需单独授权“显示在其他应用上层”。输入或应用启动失败时，不回退到主屏。

开发者仍可通过 `lifeos.md.tapilot.experiment.BackgroundDisplayActivity` 打开诊断页面，检查主屏输入焦点、手动选择测试应用和观察帧数。用户向导使用单独的试用页面，避免暴露这些诊断控制。

验证时需确认：

- 实际预览有画面，displayId 不为 0，点击后计数变化。
- 在主屏输入文字时，副屏操作不抢走焦点或改变主屏内容。
- 测试应用实际出现在副屏中；返回的启动结果本身不能证明成功。
- 关闭悬浮窗、退出试用、撤销授权或辅助死亡时，副屏和设备控制锁都被释放。
- 恢复辅助连接不自动重建副屏、不继续中断任务。

实验运行时占用应用内设备控制锁，不能与本包的正式任务或无线控制同时运行。该锁无法控制其他应用的无障碍服务。文字输入、系统导航、熄屏执行、受保护页面及支付接管仍未纳入当前副屏能力。

## 历史结果

早期实现只使用普通应用与无障碍权限，没有 Shell 辅助。[2026-11-03 Redmi 真机记录](../../tests/verification/background-display-2026-11-03.md)显示 Android 12 上可渲染和截图，但副屏手势取消、计算器启动被拒绝。该记录中的两分钟运行限制属于旧实现。

后续 Shell 路线的[模拟器验证记录](../../tests/verification/shell-display-2026-11-03.md)覆盖定向点击、Clock 启动和撤销。不同路线和设备的结果不能互相替代；当前设置流程的验证单独记录。

## 接入 Agent 的条件

仍需验证目标应用兼容性、截图来源、文字输入和系统导航如何限定到副屏，以及接管、取消和进程中断时的行为。聊天任务已有单独的可选后台执行路径；具体设备覆盖应以最新验证记录为准。

更多信息见[悬浮虚拟屏说明](floating-virtual-display.md)和 [Android 多屏启动规则](https://source.android.com/docs/core/display/multi_display/activity-launch)。
