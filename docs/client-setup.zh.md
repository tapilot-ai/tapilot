# 在 AI 客户端中使用 Tapilot

本文介绍如何把 Tapilot 接入豆包工作、WorkBuddy、Cherry Studio、DSH Web、Codex 和 VS Code，让你在会话里查看、操作 Android 手机。

更新于 2026-11-05。当前统一接入包面向 **macOS Apple Silicon（M 系列芯片）**，已通过 [0.6.18 接入预发布](https://github.com/tapilot-ai/tapilot/releases/tag/client-setup-v0.6.18) 提供公开下载。Windows、Linux 和其他架构需要另行验证。

优先打开[官网接入页](https://tapilot.lifeos.md/zh/install)，复制提示词交给当前客户端。官网同时提供无需预装 Skill 的公开 Agent 说明和手动安装入口。

## 选一个客户端

| 客户端 | 你需要做什么 | 手机画面在哪里 | 当前实测情况 |
| --- | --- | --- | --- |
| 豆包工作 | 运行接入包，添加连接器，导入 Skill | 右侧工作台中的 MCP 面板，或内置浏览器侧栏 | 英文真实会话与浏览器侧栏已跑通；MCP 稳定性仍待验收 |
| WorkBuddy | 运行接入包，在客户端启用连接器和 Skill | MCP 只读预览，或内置浏览器侧栏 | 中英文真实会话与浏览器侧栏已跑通；MCP 路径仍待原生验收 |
| Cherry Studio | 运行接入包，导入 Skill，在桌面 Work Agent 中使用 | 会话右侧的内置浏览器 | 中英文真实会话、读图和侧栏已跑通 |
| DSH Web | 在 DSH 所在电脑运行接入包，注册插件 | 会话标题处打开的 Tapilot 原生右侧栏 | 中英文真实会话、读图和侧栏已跑通 |
| Codex | 安装 Tapilot 原生插件 | 会话中的插件手机面板 | 保留现有原生插件路线；本轮未重新完成原生客户端验收 |
| VS Code Copilot | 运行接入包，启用 MCP 和 Skill | Copilot 的 MCP App 面板 | 安装和协议检查已覆盖；原生会话仍待验收 |

**DSH Go 与 DSH Web 分开验收，目前不能承诺 DSH Go 的嵌入式面板可用。** Cursor 不在本轮原生实测范围。其他支持本地命令和图片读取的 Agent，可以先使用 Skill；是否能嵌入面板，需要分别确认。

已跑通的案例可查看[实测截图](client-showcase/2026-11-05/README.md)。客户端重启、历史会话重开、断线恢复等完整流程尚未全部验完。

## 开始前准备好

- 一台已安装并登录所选 AI 客户端的电脑。该客户端需要有能调用工具、读取图片的模型。
- 一部安装了 Tapilot 的 Android 手机，并按应用提示开启设备控制无障碍服务和无线控制。当前手机端要求见[手机安装说明](../README.zh.md#开始使用)。
- 手机保持解锁，电脑与手机处于能够互相访问的网络中；首次使用可先连接同一个 Wi-Fi。
- 从官网接入页下载适合本机的 Tapilot 接入包，核对文件大小与 SHA-256。

通过客户端的 Skill 使用 Tapilot 时，由客户端的模型读取截图、决定操作。默认步骤模式不需要另外配置一套 Midscene 模型凭据；手机上独立运行 AI 任务的模型设置另行配置。

## 先运行统一接入包

适用于豆包工作、WorkBuddy、Cherry Studio、DSH Web 和 VS Code。Codex 的入口会显示原生插件安装说明。

1. 解压收到的 `tapilot-setup-darwin-arm64-版本号.tar.gz`。
2. 双击其中的 **Install Tapilot.command**，按菜单名称选择客户端。
3. 等安装和检查结束，保留终端显示的接入说明。说明也会保存为本机的 `INSTALLATION.md`，终端会显示它的位置。
4. 按下方对应平台的步骤完成客户端内的操作。

接入包自带安装所需的 Node 和依赖。安装器会把 Tapilot 放入受管理目录，后续使用不依赖源码目录，也不要求保留原始解压目录。Codex 原生插件的宿主运行要求单独见下文。

安装结果中可能出现这些字段：

| 字段或提示 | 你会在哪里用到 |
| --- | --- |
| `launcher.command` | 豆包工作添加 STDIO 连接器时的“命令” |
| `launcher.args` | 同一连接器的“参数”；这是参数列表，按界面要求逐项填写或粘贴 |
| `skillFolder` | 豆包工作、Cherry Studio 导入 Skill 时选择的文件夹 |
| `pluginDirectory` | DSH Web 注册插件时使用的目录；优先复制接入说明中生成的完整命令 |
| `manual` | 还有需要你在客户端里完成的步骤 |
| `not_tested` | 该项尚未验证；例如安装器不会替你确认真实手机画面是否已显示 |

路径由安装器生成，请使用你这台电脑上的实际值。安装器检查通过后，还需要在真实会话中打开手机面板。

## 豆包工作

### 第一次接入

1. 在接入菜单中选择 **豆包工作 / Doubao Work**。
2. 在豆包工作的 **插件 · 技能 · 伙伴** 中，添加名为 `tapilot` 的自定义 **STDIO** 连接器。
3. 将安装结果中的 `launcher.command` 填入“命令”，将 `launcher.args` 填入“参数”。这条接入方式无需额外填写环境变量。
4. 导入安装结果中的 `skillFolder`，启用 Tapilot Skill 和连接器。若当前版本支持 ZIP 导入，也可在本机运行时安装完成后，导入配套的豆包 Skill ZIP。
5. 新建一个 **本地电脑** 任务，发送：

   > 使用 Tapilot，在当前会话右侧打开手机实时面板。

个人用户可以采用这条本地接入方式，无需企业资质。

### 应该看到什么

手机面板应出现在右侧工作台。若画面收回到消息中，可使用宿主提供的 **Open in sidebar / 在侧栏打开**。如果 MCP 面板恢复一次后仍空白，让 Tapilot Skill 改用**豆包内置浏览器侧栏**打开实时预览。

独立的系统浏览器窗口可以用于查看，但与本指南中的“会话内侧栏”不同。实际可用效果见[豆包英文实测](client-showcase/2026-11-05/doubao-en-native-browser-live.png)。

### 更新时

运行新版接入包，再重新导入更新后的 Skill。安装器不能替换豆包账号中已经上传的旧 Skill。按提示重新启用连接器或重启豆包，再开一个本地电脑任务确认版本和手机画面。

## WorkBuddy

### 第一次接入

1. 在接入菜单中选择 **WorkBuddy**。安装器会配置本地连接器并链接 Skill。
2. 打开 WorkBuddy，在连接器管理中找到 `tapilot`，按客户端提示确认信任并启用。
3. 确认 Tapilot Skill 可用，新建一个任务，发送：

   > 使用 Tapilot，在当前会话右侧打开手机实时面板。

### 应该看到什么

当前有两种面板路线：

- **MCP 预览**：只读，用于看画面；配对、操作等任务交给 Skill 执行。
- **内置浏览器侧栏**：已经完成中英文真实会话实测，可显示实时画面和交互控件。

如果 MCP 面板无法显示，直接告诉 Agent：

> 请用 Tapilot Skill 在 WorkBuddy 的内置浏览器侧栏打开预览，并保留当前会话。

当前原生实测通过的是浏览器侧栏路线，见[英文示例](client-showcase/2026-11-05/workbuddy-en-showcase.jpg)。

### 更新时

运行新版接入包，重新启动连接器或 WorkBuddy，再开新任务。安装器管理的 Skill 链接会随安装更新，无需采用豆包那样的账号侧上传步骤。

## Cherry Studio

使用 **桌面版的工作（Work）Agent**。本接入方式需要本地命令和图片读取能力，普通对话或手机端不在当前支持范围内。

### 第一次接入

1. 在接入菜单中选择 **Cherry Studio（桌面 Work Agent）**。
2. 打开 Cherry Studio，进入 **设置 → 技能 → 添加技能 → 本地导入 → 从文件夹安装**。
3. 选择安装结果中的 `skillFolder`。看到“技能已安装：tapilot”，并确认它已全局启用。
4. 在工作区选择一个 Agent，在其编辑界面的技能选项中启用 Tapilot；确认该 Agent 具备 Shell、图片读取和 Browser 工具。也可以从技能卡片的 **立即试用** 进入会话。
5. 发送：

   > 请使用 tapilot 技能，在当前会话右侧的内置浏览器中打开手机实时画面。

当前无需为这条接入路线额外添加 Tapilot MCP 连接器。

### 应该看到什么

Agent 会读取 Skill、运行本地 CLI，并通过 Cherry 的浏览器工具打开会话右侧面板。首次命令执行可能需要你逐项确认，按提示核对即可。

如果 Agent 提示没有 Browser 工具，检查 Agent 的内置工具设置和 Cherry 的浏览器控制设置，按宿主提示完成启用。也可以先点会话标题栏的浏览器按钮展开侧栏，再让 Agent 继续。

见[中文实测](client-showcase/2026-11-05/cherry-zh-showcase.jpg)和[英文实测](client-showcase/2026-11-05/cherry-en-showcase.jpg)。英文案例中，Agent 自行打开并导航了右侧浏览器。

### 更新时

运行新版接入包；Skill 内容变化后，在 Cherry 中重新导入，并确认对应 Agent 仍启用了它。已有导入副本不会仅因本地运行时更新而自动替换。

## DSH Web

接入包要在**运行 DSH 的电脑**上执行。若 DSH 在远程主机上运行，应在那台主机上安装和配对，不能直接套用你当前电脑的本地路径。

### 第一次接入

1. 确认 DSH Web 已能正常打开，并已配置可用的模型。当前插件适配 DSH `>=0.2.1-rc.5 <0.3.0-0`。
2. 在该主机的接入菜单中选择 **DSH Web**。
3. 按接入说明，在 DSH 主机的终端执行生成的插件注册命令。若使用自定义 `DSH_HOME`，沿用说明中的值。
4. 重新加载或重启 DSH Web。在会话标题处选择 **Tapilot**，打开原生右侧栏。
5. 在同一会话中让 Agent 使用 Tapilot 读取手机。

全局 Tapilot 入口会打开专用面板页；要同时看到会话和手机，请使用**会话标题处的入口**。

如果 Agent 无法点击这个界面入口，你可以手动点开后再让它继续。见[DSH 英文实测](client-showcase/2026-11-05/dsh-en-showcase.png)。

### 更新时

运行新版接入包，重新加载或重启 DSH。旧安装若仍注册在某个版本目录上，按新接入说明迁移到固定插件目录一次；之后更新继续使用这个固定入口。

## Codex

Codex 使用 Tapilot 原生插件。统一接入菜单中的 Codex 选项会显示安装说明，不会自动完成插件安装，也不会另外创建一套连接器。

当前本地安装需要维护者提供带有 Tapilot 插件市场配置的**仓库根目录**。在该目录打开终端，执行：

```sh
codex plugin marketplace add .
codex plugin add tapilot@tapilot-local
```

这里的 `.` 必须是带插件市场配置的目录，不能换成统一接入包的解压目录。原生插件仍需要宿主能运行受支持的 Node.js（当前要求 22.19 或更新版本）。

加载插件后，在会话里发送“打开 Tapilot 手机面板”。更新按 Codex 的原生插件管理方式处理，并重新加载插件宿主。原生插件市场的公开分发入口仍需维护者提供。

## VS Code Copilot

1. 在接入菜单中选择 **VS Code Copilot**。
2. 安装器会合并 MCP 配置并链接 Skill。在 VS Code 中按提示信任、启动 Tapilot MCP 服务器。
3. 使用已登录、可用的 Copilot Agent 模式，新开会话，让它打开 Tapilot 手机面板。

该路线已覆盖配置和协议检查，尚未完成本轮原生客户端实测；采用前请先验证真实会话和手机画面。

## 第一次连接手机

上述平台完成接入后，先在客户端发送：

> 打开 Tapilot 手机面板，我要配对一部 Android 手机。

1. 在手机上打开 Tapilot，保持设备解锁，并确认无线控制已开启。
2. 在电脑上的 Tapilot 交互面板中开始配对；若当前面板仅提供只读预览，让 Agent 帮你打开配对页面。
3. 使用**手机 Tapilot 内的扫码入口**扫描配对二维码，并按页面提示在电脑上确认。
4. 选择该设备，确认面板显示“已连接”，并能看到当前手机画面。

同一台电脑、同一系统用户下的客户端共用 Tapilot 配对。若换成另一系统用户或另一台 DSH 主机，需要按那个环境重新配对。

为了核对第一次接入，可以先手动把手机停在系统设置页，再发送：

> 使用 Tapilot 读取当前手机屏幕，用一句话描述你看到的内容，并保留右侧实时画面。只做读取，不点击、不输入、不切换设备。

确认回答与手机画面一致，并能打开执行报告。看到“安装成功”、模型回答“已打开”，都还需要与实际显示的画面核对。

## 常见问题

| 现象 | 可以先做什么 |
| --- | --- |
| 安装完成，会话里没有 Tapilot | 检查连接器或 Skill 是否启用，是否绑定到当前 Agent；开一个新会话再试 |
| 面板灰屏或空白 | 恢复一次面板；豆包工作和 WorkBuddy 可让 Skill 改用客户端内置浏览器侧栏 |
| 打开了一个文件卡片，提示文件不存在 | 请 Agent 将预览地址作为网页放入内置浏览器，避免把地址当成本地文件打开 |
| Cherry 只回答文字，没有执行工具 | 确认在桌面 Work Agent 中使用，模型支持工具调用，Tapilot Skill 和必要工具已启用 |
| DSH 只有单独的手机页，没有会话 | 回到会话，从会话标题处的 Tapilot 入口打开右侧栏 |
| 显示认证失败或模型错误 | 先修复客户端模型连接；Tapilot 安装成功不代表客户端模型配置成功 |
| 显示已配对，但没有实时画面 | 检查手机是否解锁、无线控制是否开启、网络是否可达，以及设备是否已连接 |
| 手机被其他控制器占用 | 先在原控制器释放，再在目标客户端连接 |
| 画面处于隐私暂停 | 完成私密操作后，由你明确恢复；不要让 Agent 反复重连 |
| 更新后仍显示旧版本 | 重启连接器或客户端；豆包工作、Cherry Studio 还需检查是否重新导入了更新后的 Skill |

如果向维护者反馈问题，请提供客户端版本、Tapilot 版本、失败发生在哪一步，以及不含隐私信息的截图或报告。

## 后续如何维护

- **升级**：获取新版接入包，选择同一个客户端，再按提示重载。当前采用离线安装包更新，尚不支持无人值守的网络自动升级。
- **本地路径**：路径是安装器生成的正常安装入口。填写安装结果中的值即可，无需把开发者源码路径写进客户端。
- **现有配置冲突**：如果安装器提示原有条目或 Skill 被修改，保留现场交给维护者检查，不要先删除用户配置来强行覆盖。
- **停止使用**：告诉 Tapilot 断开并释放手机。移除客户端接入时，豆包工作和 Cherry Studio 中手动导入的 Skill、DSH 中的插件注册还需在各自宿主中移除。移除一个客户端的接入与删除手机配对是两件事。

需要排查安装细节时，可查阅[开发者接入说明](../plugins/tapilot/CLIENTS.md)；各平台的实测边界见[原生验收记录](../plugins/tapilot/NATIVE-ACCEPTANCE.md)。
