# 品牌配色、语音反馈与真机验收

## 当前实现

聊天界面继续使用 Kotlin／Compose，对话 Agent 管理消息与任务上下文，Midscene 执行手机操作。设置和 Agent 运行环境仍由已有 WebView／Node 承载。

`theme/brand.json` 统一维护 Midscene 蓝紫色和明暗主题角色，生成 Kotlin、Android 资源与 CSS。聊天、设置、悬浮入口和报告页引用这些产物。修改配色后运行 `pnpm theme:generate`；前端及 Android 构建都会检查生成文件是否同步。

语音界面沿用用户提供的微信参考布局，气泡使用 Midscene 蓝紫渐变。上滑进入取消区域只显示“松开取消”，移动回来可以恢复，松手才取消。文本框也支持长按录音。

波形读取 16 kHz 单声道 PCM 的实际音量，使用对数刻度显示，替换固定动画。界面显示录音时长，录音最长 60 秒。失败录音只保存在内存，最多手动重试两次；成功、关闭错误、新录音、切换会话或关闭控制器会清理。转写成功追加到原草稿，取消和失败保留草稿。

## 自动检查

前端 67 项测试、Android 78 项测试、报告导出 3 项测试通过；TypeScript 检查、品牌产物检查、前端构建及 Android debug APK 构建通过。

额外修正了 60 秒边界：最后一个麦克风缓冲块按剩余容量截断，避免块大小导致 PCM 超出上限。

失败恢复使用 `tapilot.debug.failSpeechOnce` 启动参数；仅 debug APK 生效。这验证重试逻辑，不代表已经测过真实弱网。测试时从全新 Activity 启动该参数；首次在现有实例投递参数未触发注入，后续重新启动后确认错误提示为注入错误，再执行重试。

一次在任务结束后直接断言“当前屏幕仍是计算器”失败：任务完成后应用会返回聊天。后续改为检查执行报告中的操作截图与当时的断言，确认计算器已经打开。任务结果以这份执行证据为准。

测试使用本机已有、可用的 `qwen3.7-plus` 模型临时跑完整链路。原 `custom / qwen3.5-plus` 配置此前连接测试被服务拒绝，测试结束已恢复原配置，并清理临时模型配置。用户继续执行任务前还需要修复这份模型配置。
