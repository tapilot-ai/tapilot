# 失败重试与可配置任务上限

## 行为

- 失败或停止消息下提供“重试”；复用原消息和附件，创建新任务 ID、执行会话与开始时间，计时和手机操作/模型轮次从零开始。旧结果保留，新尝试通过 retryOf 关联；不会继承旧执行的工具上下文。
- 设置 → 任务与记录：手机操作次数上限、对话轮次上限分别可设置正整数，也可关闭为“无限制”。默认 100/101，设置存入原生私有会话存储，每个新任务/重试开始时读取快照。
- 两个上限彼此独立；单独关闭一个不会关闭另一个。手机上限计算完整 Midscene 工具调用，不是单次点击。关闭后不再存在隐藏的 4 次、8 轮、100 次硬限制，手动停止仍有效。

## 验证

- Gradle testDebugUnitTest + assembleDebug 通过，137 项原生测试、0 失败。新增测试覆盖设置持久化、非法配置回退、自定义次数、自定义轮次、每次调用重新计数、关闭上限后 120 次工具调用和手动停止。120 次为测试桩，不冒充真机长任务。
- Redmi K30 Ultra s4ey59ytbitot4yp 安装修复开发包，实际设置手机上限 1、对话上限 2。发送“Open Calculator and verify its keypad.”，由于设备控制未连接正常失败；点击“重试”后显示 0s，并以新任务重新执行，失败后的重试按钮依旧可用。
- 对私有存储仅提取两个验证任务的 ID、createdAt、retryOf、status 及 agentLimits，验证重试关联正确、开始时间更新。未导出 API Key、用户历史或模型响应。
- UI 分别关闭两个上限，保存为“无限制”；强制停止并重启应用后，两项仍显示“无限制”。真机当前保留此配置。聊天和原 YOLO 配置保留。
- 使用 ADB 截图驱动视觉验收；未声称通过设备控制执行了计算器任务。设备会话已释放，未改网络。
- 开发包仍为 0.1.2/code3，飞书公开发布包没有替换。公开发行应另行递增版本。

## 默认值调整

按用户后续要求，两个默认上限统一为 100。关闭后重新启用时输入框也默认显示 100；用户明确保存的自定义值或关闭状态继续保留。测试手机恢复为两个上限均启用、值均为 100。
