# Tapilot 界面基准

打开 [截图总览](index.html)，逐图比较界面。布局依据用户提供的微信语音截图，主色依据 Midscene 蓝紫色；聊天保持原生 Kotlin／Compose 实现。

| 文件 | 检查内容 |
| --- | --- |
| chat.png | 标题栏、消息、输入栏、品牌颜色 |
| keyboard.png | 键盘弹起后输入栏与草稿可见 |
| recording.png | 全屏录音提示、真实音量波形、时长 |
| cancel.png | 红色气泡与“松开取消”，上滑尚未结束录音 |
| transcribe.png | 转文字区域与松手提示 |
| attachment.png | 照片、拍摄、文件入口 |
| settings.png | 独立设置页及颜色 |
| report.png | 真实任务报告与执行截图 |

设备：Xiaomi M2006J10C，MIUI 14，1080 × 2400。聊天及报告来自本次火山语音打开计算器任务；键盘和录音使用测试草稿／语音，没有使用虚构回复。失败恢复的两张附加截图也来自真机。

截图采集跨本次两个 debug 构建：录音、键盘和失败恢复截图在 60 秒缓冲区截断修正前采集，其余截图在最终 APK 上采集。两次构建使用同一套界面与配色；截断修正仅影响录音长度边界。完整任务链路在此前同轮 debug 构建验证，随后新增的波形显示调整与边界修正未重新执行任务链路。

`manifest.json` 记录实现提交、主题哈希与八张截图的哈希。执行 `pnpm baseline:check` 检查截图完整性和主题是否变化。该检查不判断界面是否正确；更新基准前必须人工逐状态核对，不能仅运行脚本覆盖。

重新采集时使用 Android 设备锁，并根据截图定位操作。瞬态录音状态需要同一个持续按压手势，避免每次移动都变成新的点击。图片准备好后运行 `node scripts/visual-baseline.mjs`，再运行完整性检查。
