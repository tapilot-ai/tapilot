## 方法与边界

Android Use Wi-Fi 控制器断开，检查没有到手机的 TCP 连接。使用已授权的 USB 调试作为外部测试工具安装 APK、按下语音入口、采集截图和日志。Mac 扬声器播放中文测试音频，手机真实麦克风采集；未向输入框注入测试文字。识别、联网模型请求、任务执行和语音播放均由手机应用完成，未由 Codex/Claude/CLI 执行任务步骤。

这证明手机运行路径不依赖电脑控制服务，但不是物理拔掉 USB 后的测试。语音服务和模型仍需要手机网络。测试结束恢复 Mac 原音量 50 和静音状态，并关闭手机麦克风。

## 结果

- 长按输入框可真实录音并填入草稿。句子“打开系统设置，查看安卓版本，不要修改任何设置”中的“安卓”识别为“安装”。发送原始识别结果后，手机打开关于本机并看见 Android 14，但因歧义追问；任务 `cfc80f5d-eac6-404e-b055-bb329cbfd535` 为 waiting_user，51.735 秒。不能计作完整识别或任务成功。
- 连续语音首次受到环境人声干扰，自动提交了非预定内容；已结束监听，不计作测试句通过。
- 连续语音完整识别“12+34等于多少？请用语音回答。”，但旧模型提示未说明应用的朗读能力，回复“无法发送语音”。任务 `b8b75f0f-4ce6-4c02-b901-4f7b0b4449f8` 为 waiting_user，15.695 秒。
- 修复 `NativeConversationAgent` 中英文系统提示：应用负责按语音设置朗读文本；模型提供适合朗读的答案，不得因返回文本而拒绝口头回答，也不得无证据宣称音频已播放；发送语音消息/生成文件仍是独立操作。
- 修复版相同完整语音指令得到“十二加三十四等于四十六”。旧会话任务 `0e29eb5e-cb72-454a-9a0e-78e2c058aa06` 仍标记 waiting_user（11.479 秒），状态残留问题未解决，不计作终态成功。音轨于 19:07:08.712 开始，19:07:10.796 停止。
- 新会话识别并自动提交“12+34等于多少？”，回答“12+34=46。”，任务 **`d4f1c3aa-ea29-4b8a-bd6f-6fff4f2a6ac3` succeeded，3.039 秒**。测试音频后半句未进入这条消息，因此只计作该算术语音问答通过，不能计作整句识别通过。
