## 仍需区分的边界

- `ServiceGateway` 继续兼容原生设置页和旧 WebView；本轮对任务运行入口建立类型化边界，没有宣称所有内部 JSON 已消除。
- `ReportActivity` 仍管理 viewer、主题和加载状态；导出已独立，不再将单纯移动 Activity 文件当成职责拆分。
- 未新增针对某个应用、桌面分组或计算器任务的识别逻辑。模型仍根据截图规划，执行仍经过 Midscene 和独立画面核验。
- 本地 JVM／Node 测试不验证 Android 麦克风、真实手势、OEM 生命周期、插件宿主窗口和新增原生包的实际运行。

## 验证记录

首次审查完整 Lint 为 1 错误、59 警告、3 提示。首次现有目录构建在图标资源目录合并后遇到旧增量资源链接错误；清理生成目录后构建通过。第一次隔离目录构建在旧 Termux 下载路径返回 404 时失败，这一失败推动了固定版本更新，不能被本地缓存的成功覆盖。

本轮最终门禁、构建指纹、静态检查、基准与设备状态见[当前验收入口](validation-current.zh.md)。成功和失败分别保留在本地验证日志中。

3. APK 分发继续受第三方材料门禁阻断。剩余 Sharp WASM、proxy-agent-negotiate、secure-compare，以及 Termux 原生依赖的 notices／对应源码／重建材料需补齐；不修改批准标志绕过检查。细目见[材料说明](../../third-party/README.md)。
4. 正式签名、上架和公开发布是独立步骤。本轮仅生成供验收的本地签名 Beta APK。

## 静态检查中的保留项

完整 Lint 持续运行且没有新增忽略基线。剩余 `UseKtx` 为写法建议，六个未引用颜色来自跨端共享主题生成器；SDK 35 升级需要单独做 Android 行为验收。扫码纵屏是既有产品要求；OEM 圆角资源查询有缺失回退；电脑配对的自定义信任管理器校验扫码获得的证书指纹和有效期，并非信任所有证书。这些保留项不能用修改 baseline 来隐藏。
