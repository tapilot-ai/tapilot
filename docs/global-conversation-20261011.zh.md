# 全局对话与打断（2026-10-11）

## 交互

参考 Studio 中 Vibelet 的 `chat-composer.test.ts` 和 `chat-store-control-actions.ts`：任务执行中仍可输入，带草稿时发送新消息，空草稿时停止。

- 全局入口复用原生聊天页，可连续追问、查看回复、展开到主界面、收起回原应用。
- 面板与主界面共用一个 `NativeConversationCoordinator`，使用同一份历史和配置。
- 执行中继续输入文字、录音或添加附件；发送后先停止旧任务，再处理新消息。
- 手机操作期间可点顶部“正在处理 · 点击打断”，重新打开会话并停止当前任务。
- 保留已停止轮次的用户请求和实际返回的手机操作结果。没有返回的操作不能当成已完成。
- 停止包括模型 HTTP 请求、无障碍会话和 Node 执行器；等待执行器收尾后才启动下一条消息。旧任务延迟的界面跳转也随取消失效。

生产版本不再使用旧的单次输入面板。旧面板仅留在 `speechVerification` 源集，供已有语音验证入口使用。普通 APK 的会话、全局输入和配置仍由 Kotlin / Compose 实现。

## 真机验证记录

设备：Redmi K30 Ultra，`s4ey59ytbitot4yp`。使用跨会话 Android 设备锁；安装保留应用数据。Midscene 通过系统正常界面开启设备控制服务。

已完成的场景：

- 全局面板显示在桌面上方，回复后保持打开。
- 收起后从悬浮球重新打开，追问上一轮的标记，实际模型返回 `ORCHID42`。
- 全局面板和完整聊天页都能弹出键盘，输入及发送位于键盘上方。
- 新会话中发送长回复请求，在仍显示“正在处理”时输入并发送新消息：旧请求状态为 `stopped`，新消息为 `succeeded`，实际回复 `PINE94`。

第一轮长回复测试中旧请求提前完成，该轮没有发生打断，不作为打断通过证据。后续新会话测试保存了执行中截图、停止后的截图和私有状态的脱敏摘要。

最终构建与安装验证：

- `testDebugUnitTest assembleDebug --max-workers=2 --no-parallel --no-daemon` 通过；140 项测试通过，1 项真实语音润色服务测试因未配置本次测试环境而跳过。
- 手机操作执行器启动后，点顶部状态条打断，旧任务为 `stopped`，随后对话为 `succeeded` 并回复 `STOPPED`。Node 有本次启动日志；停止后应用子进程为空。此次在计算器操作完成前取消，没有把任何计算结果当成完成证据。
- 最终 APK 的全局面板中，空输入框停止按钮正常取消请求，继续追问回复 `FIR97`，停止轮次仍保留在上下文中。
- 从设置页回桌面后点击悬浮球，直接打开聊天页，保留上一轮回复；展开回完整聊天页继续使用同一会话。
- 安装前的 46 条历史全部保留，模型预设、YOLO 模式和两个 100 次上限配置一致。
- 手机安装包与最终构建 APK 的 SHA-256 一致：`6743529d3fe2802f53e4943f4e1d96b2a8ad668cab587a4b54c5bcf10e79a163`，大小 89,506,931 字节。

系统键盘按钮变化导致有一轮草稿合并，该轮未作为打断证据；最终改用应用内按钮，并在干净会话中完成停止及上下文追问。

本轮未重新验证火山引擎 / Deepgram 的实际麦克风转写、语音润色接口或附件发送。执行中的录音和附件入口已解除锁定，沿用已有原生实现。
