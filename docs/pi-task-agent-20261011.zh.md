# Tapilot 任务 Agent 接入

## 实现

- 使用 Pi 官方当前包名 `@earendil-works/pi-agent-core` / `pi-ai`，固定为 1.1.0。
- Pi 在独立 Android Node 子进程中管理上下文和模型/工具循环；原生 Kotlin 保留界面、任务记录、API 请求、凭据和手机控制。
- Pi 通过限定的 stdio RPC 调用原生 `model.complete`、`phone.execute`。模型 API Key 不传入 Pi 的环境或消息。
- `set_plan` 保存步骤；`operate_phone` 调用 Midscene 执行并验证画面；`finish_task` 完成任务或提出问题等待用户补充。
- Midscene 只收到本次操作指令和成功条件。手机工具始终串行执行。
- 原有 Kotlin 模型循环已删除；旧对话记录仍通过原生上下文转换器导入 Pi。

## 交互和恢复

- 任务执行中的文本消息进入当前 Pi 的 steering 队列，当前手机操作结束后再调整后续步骤。
- 空输入框的停止按钮、全局执行状态条和明确的停止消息会取消任务，同时停止模型请求、Pi 和 Midscene。
- 任务目标、计划、操作结果、模型轮次、操作次数和 Pi 上下文持续保存。补充消息在提交给 Pi 前保存，尚未消费的补充信息可随任务恢复。
- 重试/继续使用保存的上下文。缺失的工具结果标为“执行结果未知”，要求先核验实时画面，不能假定成功或盲目重复操作。
- 等待补充的任务会承接下一条用户消息；重启后的运行中任务标为暂停，不自动执行手机动作。
- 新尝试重新计时、重新计数；默认两种上限各为 100，现有设置可自行修改或关闭。
- 执行中的附件沿用打断后进入下一轮的路径；纯文本补充使用同任务 steering。

## 验证

自动化：17 项 Pi 核心测试通过；原生单元测试 135 项通过，1 项需要外部语音服务的测试跳过。

真机：Redmi K30 Ultra，ADB `s4ey59ytbitot4yp`。首次安装后，实际完成“打开计算器，然后计算 3+4”：

- 保存了两步计划。
- 6 次模型调用、2 次 Midscene 手机工具调用。
- 两次工具调用都通过最终画面断言；结果为 7。
- 任务状态为 succeeded / completed，保存 16 条 Pi 上下文消息。
- 任务结束后没有残留 Node 子进程。

验证证据目录：`artifacts/20261011-pi-agent/`。补充与恢复：

- 执行中输入补充消息后，仍为同一任务，保存补充输入 ID；最终回复 CEDAR83。
- 模型调用已开始（轮次 1）后，点击停止，任务变为 paused，16 条上下文保留，Node 子进程退出。
- 强制关闭并冷启动后，暂停记录和上下文保持一致，没有自动启动 Node 或手机操作。
- 发送 continue 后，以同一个 taskId 恢复，attempt 增加到 2，计数从 0 重新开始，恢复原有 16 条上下文；随后回复 FIR88。
- 补充指令早于首轮模型调用时也能进入 Pi 队列。本次真实补充测试覆盖该路径；工具执行中的 steering、未消费消息的恢复由 Pi 核心测试覆盖。

- 强制停止导致 MIUI 无障碍服务断开，已通过正常系统设置重新连接；不是任务恢复流程自动授予权限。
