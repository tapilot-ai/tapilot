# 长按语音提前采集（2026-10-09）

## 改动

符合长按语音条件的空输入框，在手指按下时就准备 AudioRecord。已有麦克风权限才准备，不因轻点请求权限。至少 32768 字节的硬件缓冲保留长按判定期间的开头，确认长按后接管同一个 AudioRecord，开始读取并连接 ASR。

轻点、移动、取消、窗口失焦、输入框卸载时释放准备状态。准备状态有 700 毫秒超时保护；正常长按仍在 280 毫秒确认。已有文本（包括空格）和已聚焦的输入框沿用普通编辑行为。松手默认回填文本，取消和发送逻辑保持现有规则。

SpeechRecognition 新增 prepare / cancelPreparation；润色包装层转发准备操作，不提前启动识别或润色。聊天和全局助手面板输入框接入相同的准备接口。

## 验证

- `testDebugUnitTest assembleDebug -PspeechVerification --max-workers=2 --no-parallel --no-daemon` 通过，127 项测试通过、1 项跳过。
- 独立验证 APK 在 LifeOS Backup Pixel 7 模拟器运行，使用生产原生输入框、手势和聊天控制器，替换为合成识别源。
- 长按：准备 1 次、录音启动 1 次、发送 0 次，完整回填“开头两个字，保留最后两个字”。合成源只有在准备接口先被调用时才包含开头。
- 100 毫秒轻点：准备 1 次、丢弃 1 次、录音启动 0 次、发送 0 次；草稿为空，键盘正常出现。
- 截图、UI XML 与 APK SHA-256：`docs/visual-baseline/20261009-speech-pre-capture/`。

这轮证明准备操作与原生手势正确衔接，没有使用真实音频、API Key 或用户数据；实际麦克风启动速度和快速开口的准确率仍需在手机上验证。测试 APK 与模拟器已清理，未安装到用户真机，未提交、推送或发布。
