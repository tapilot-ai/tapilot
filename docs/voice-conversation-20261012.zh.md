# 全局语音对答

## 使用方式

- 普通聊天默认朗读新回答，设置中可关闭「自动朗读助手回答」。单条回答提供「朗读 / 停止播报」，打开旧会话不会把历史消息全部读一遍。
- 点击输入框右侧声波开始连续对话。收到指令后立即发出短提示音，同时通过当前 API 音色回应「收到」，任务不等待播报就开始处理。
- 开启语音后可切到其他应用。回答、追问和下一轮录音继续运行；语音任务完成后不强行切回主界面。
- 返回键收起界面。主界面和通知栏均提供暂停、继续、打断和结束语音。结束语音不取消已提交任务，但会停止当前及待完成任务的自动播报；再次发送消息恢复默认播报行为。
- 30 秒没有说话会暂停监听。播报期间麦克风关闭；打断入口会停止播报并重新监听。目前不支持唤醒词或说话直接打断。

## 实现

`AssistantRuntime` 使用 Application Context 持有 Pi 对话上下文、转写和播报。页面只附着状态观察者和交互入口；页面销毁后移除这些引用，任务和音频不会随页面销毁。原生服务桥仅以弱引用附着 Activity，后台操作使用应用 Context。

`VoiceRuntimeService` 按 Android 要求声明 `microphone|mediaPlayback` 前台服务类型和对应权限。麦克风服务由可见页面开启，已授权后才录音，不从后台请求权限。通知提供用户可见的语音状态和停止入口；不设置自动重启，进程结束后不会自行开启麦克风。

普通回答由 `ReplySpeech` 管理完成状态、旧消息去重和过期播放回调。连续对话启用时停止普通播放器，避免重复播报。回执播放与模型处理并行；回执失败不会丢弃后续结果。

API 沿用火山 Seed ASR / Seed TTS 与 Deepgram Nova-3 / Aura-2。模型仍使用当前配置，Midscene 仍只执行具体手机操作。

Android 接入依据：[前台服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)、[后台启动限制](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)。

## 验证

构建、158 项 Kotlin 单元测试通过，其中 21 项覆盖语音停顿、回执与快速回答衔接、回执失败、旧回答去重、切会话和过期回调。

Redmi K30 Ultra（`s4ey59ytbitot4yp`）已安装测试版，保留火山转写、百炼订阅模型配置。两轮固定普通话录音由独立测试 APK 播放，通过手机真实麦克风、火山 ASR、百炼模型和火山 TTS 完成，未向转写或模型注入模拟结果。两轮全程停留在计算器：

1. 「请先问我喜欢什么颜色」→「你喜欢什么颜色？」
2. 「我喜欢紫色」→「你的答案是紫色。」

两轮均完整识别原测试句子，手机操作次数为 0，回答与回执均播放到最后一帧；API「收到」分别在任务记录创建后 0.385 / 0.440 秒开始播放，100 毫秒提示音在收到指令时立即触发。第二轮保留第一轮对话上下文，期间没有切回主程序。

通知栏结束语音验证通过：通知移除、语音前台服务退出、麦克风不再采集。30 秒无语音自动暂停也在通知栏确认。最初 Mac 扬声器声学验证混入现场声音，未计为通过；改用手机固定录音后通过。
