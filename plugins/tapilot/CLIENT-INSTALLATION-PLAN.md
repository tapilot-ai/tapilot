# 客户端安装与分发

当前版本已实现受管安装，仍从源码或经过验证的本地包启动首次安装。`tapilot` 尚未发布到 npm，不能把 `npx tapilot` 当作可用命令。

## 已实现

- 明确指定 `--client`。`detect` 只提供建议；未指定目标的 `install` 返回选择提示，不写客户端配置。用户明确选择优先于探测结果。
- 安装时复制代码、依赖和当前受支持的 Node，放到 `~/.local/share/tapilot/clients/<client>/releases/`。复制会解开指向源码或 npm 缓存的符号链接。
- 先验证受管副本，再更新客户端配置、Skill 和安装记录。探测失败保留原安装；配置冲突和用户编辑过的 Skill 会中止安装。
- 导出的 Skill 和 MCP 启动器读取安装记录。移动原始源码、删除原始 Node 后仍可启动；升级后旧 GUI 启动项可以使用新记录。旧运行版本保留给现有会话和已保存的 GUI 命令。卸载会清理空闲运行版本；有受管进程仍在运行、DSH 注册待移除或无法确认进程状态时保留代码，避免影响其他客户端共用的后台服务。
- WorkBuddy、VS Code、Cursor 自动合并本地配置并链接到规范目录中的 Skill。保留注释、其他连接器和用户设置。
- 豆包工作返回 STDIO 启动项及可上传的 Skill 文件夹。DSH 返回受管副本中的插件路径及官方注册命令。Codex 保留原生插件通道，不重复注册 MCP。
- `install --client skill` 只导出 Skill，不配置 MCP。无嵌入面板能力的宿主走这条路径。
- Skill 包含接入引导；`doctor` 检查已安装的 Skill 启动器、配置和实际连接器，分别报告协议、原生渲染、手机验收状态。

## 各宿主剩余步骤

| 客户端 | 安装器完成 | 宿主侧步骤 |
| --- | --- | --- |
| Codex | 返回原生插件安装说明 | 安装或更新插件，重载宿主 |
| 豆包工作 | 准备稳定启动项、Skill | 界面注册 STDIO、上传并启用 Skill，开始本地电脑会话；内容更新后重传 Skill |
| WorkBuddy | 配置连接器、链接 Skill | 首次信任和启用，打开新会话 |
| VS Code | 配置连接器、链接 Skill | 登录 Copilot，信任和启动连接器 |
| DSH Web | 准备原生插件和 Skill | 执行返回的官方注册命令，重载页面；升级后注册新路径 |
| DSH Go | 与 DSH 主机共用运行环境 | 仍需实际客户端逐路由验收，不能从 Web 推断 |
| Cursor | 配置连接器、链接 Skill | 按用户要求不继续原生测试 |
| 其他 Agent | 可导出纯 Skill | 按宿主机制安装，需要本地命令与图片读取工具 |

STDIO 由宿主启动本地进程，因此绝对路径是正常配置；现在路径属于受管安装目录，不再依赖开发 checkout 或 npx 缓存。初次迁移豆包的旧连接器时，仍需把界面中的命令改为安装器返回值。

## 验证与边界

隔离集成测试实际删除源码目录和原始 Node，再启动导出的 Skill 和 MCP；同时覆盖成功升级、旧 GUI 启动项使用新安装记录、失败升级保留原安装。完整回归包含现有面板、隐私暂停、配对和运行时升级测试。

这些测试不能替代各平台的原生会话和真机验收。此前各宿主的实际结果和阻塞见 [NATIVE-ACCEPTANCE.md](NATIVE-ACCEPTANCE.md)。本次安装改造需另做原生迁移验证。

网络下载器、公开发布、自动更新服务及通用的一键宿主注册尚未实现。安装器复制当前机器上受支持的 Node，不跨操作系统或 CPU 架构分发运行时。用户配对、报告和隐私暂停状态不属于安装目录，安装及卸载都不覆盖。
